CRO reproduces the simulated ENSO characteristics in climate models#

This tutorial demonstrates how to use mCRO to calibrate the stochastic Recharge Oscillator (RO) model against output from a climate model ensemble. Using the CESM1 Large Ensemble (CESM1-LE) as an example, we show how the fitted RO can reproduce the simulated ENSO dynamics and statistics of a comprehensive Earth system model.

Unlike the previous tutorial, which focused on observations, this example illustrates how mCRO can be applied to climate model simulations. The same workflow can be readily extended to other CMIP6 models, single-model initial-condition large ensembles (SMILEs), or coupled model experiments.

Starting from simulated Niño3.4 SST anomalies and Warm Water Volume (WWV), we will

  • fit Recharge Oscillator parameters for every ensemble member,

  • estimate the ensemble-mean RO parameters,

  • perform long stochastic ensemble simulations using the fitted ensenble mean parameters,

  • compare the simulated RO statistics with those of CESM1-LE, and

  • evaluate how well the simplified stochastic model reproduces the model’s ENSO behavior.

This notebook was contributed by Soong-Ki Kim.

Contacts: Sen Zhao zhaos@hawaii.edu, Soong-Ki Kim soongkim@postech.ac.kr

Loading CESM1-LE ENSO data#

We begin by loading monthly Niño3.4 SST anomalies and Warm Water Volume (WWV) from the CESM1 Large Ensemble (CESM1-LE).

Each ensemble member represents an independent realization of internal climate variability under identical external forcing. Together, these members provide an ideal dataset for estimating robust Recharge Oscillator parameters and quantifying uncertainty associated with internal variability.

The CESM1-LE ENSO dataset is included in the “/Data” folder of the MATLAB CRO package as “CESM1_LENS_ENSO_timeseries.nc”. The dataset covers the period from 1920 to 2100, corresponding to 2172 monthly time steps, and includes 39 ensemble members.

Note that the Python version of CRO (pyCRO) provides the pyCRO.ROdata_load function for directly loading this dataset. The MATLAB version does not include an equivalent data-loading function. Therefore, users need to load the NetCDF file manually, as shown below.

Fit the Recharge Oscillator to each ensemble member#

The Recharge Oscillator parameters are estimated independently for every ensemble member.

Because the CESM1 Large Ensemble contains 39 realizations, we use parallel processing to accelerate the fitting procedure. Each member yields one set of physically interpretable parameters describing

[3]:

par_option_T=struct("R",3,"F1",3,"b_T",1,"c_T",1,"d_T",1);
par_option_h=struct("F2",3,"epsilon",3,"b_h",1);
par_option_noise=struct("T","red","h","red","T_type","additive");


for im=1:39
    fit_results{im}=RO_fitting( ...
        Nino34(:,im),WWV(:,im), ...
        par_option_T,par_option_h,par_option_noise);
end

Compute ensemble-mean RO parameters#

Individual ensemble members exhibit natural variability in their fitted parameters.

To obtain a representative Recharge Oscillator for CESM1, we aggregate the fitted parameters across all ensemble members and compute the ensemble-mean parameter set. This averaged parameterization captures the characteristic ENSO dynamics simulated by the climate model while reducing the influence of internal variability.

The resulting parameters can also be visualized to compare the relative strengths of different physical processes represented by the Recharge Oscillator.

model_fit_em=aggregate_RO_parameters(fit_results,"mean");

Seasonal modulation of ENSO amplitude#

One of the defining characteristics of ENSO is its seasonal synchronization, with variability peaking during boreal winter.

Here we compare the seasonal evolution of Niño3.4 standard deviation between CESM1-LE and the stochastic RO simulations to assess whether the fitted model reproduces the model’s seasonal phase locking.

[6]:

model_seaSD=seasonal_statistic(Nino34,"std");
RO_seaSD=seasonal_statistic(Nino34_RO,"std");


month_name={'Jan','Feb','Mar','Apr','May','Jun','Jul','Aug','Sep','Oct','Nov','Dec'};

Autocorrelation / Cross correlation#

Next, we evaluate the temporal evolution of ENSO using autocorrelation and cross-correlation analyses.

These diagnostics assess whether the Recharge Oscillator reproduces

  • the persistence of Niño3.4 SST anomalies,

  • the recharge of equatorial Pacific heat content prior to El Niño development, and

  • the discharge process following ENSO peak events.

Agreement between the stochastic simulations and CESM1 indicates that the fitted RO captures the essential coupled ocean-atmosphere dynamics governing ENSO evolution.

maxlags=36;
[lags,model_acf,model_ccf]=ensemble_xcorr(Nino34,WWV,maxlags);
[~,RO_acf,RO_ccf]=ensemble_xcorr(Nino34_RO,WWV_RO,maxlags);

ENSO spectrum analysis#

Finally, we examine the frequency characteristics of the simulated ENSO variability using Thomson’s multitaper spectral estimator.

The observed ENSO spectrum is characterized by

  • a dominant peak near 2.5–5.5 years (``fE``), corresponding to the intrinsic ENSO oscillation, and

  • weaker combination modes (1-fE and 1+fE) produced by interactions between the annual cycle and ENSO.

Matching the simulated spectrum provides a stringent test that the simplified stochastic model captures the principal timescales of ENSO variability simulated by CESM1.

Reference: Stuecker, M. F., Timmermann, A., Jin, F.-F., McGregor, S., & Ren, H.-L. (2013). A combination mode of the annual cycle and the El Niño/Southern Oscillation. Nature Geoscience, 6(7), 540–544. https://doi.org/10.1038/ngeo1826

Summary#

In this tutorial, we

  • fitted the Recharge Oscillator to every CESM1 Large Ensemble member,

  • estimated representative ensemble-mean RO parameters,

  • generated long stochastic ensemble simulations,

  • reproduced the simulated seasonal synchronization of ENSO,

  • captured the nonlinear asymmetry between El Niño and La Niña,

  • recovered the recharge–discharge relationship between Niño3.4 SST and WWV, and

  • reproduced the dominant spectral characteristics of ENSO simulated by CESM1.

This workflow demonstrates that mCRO provides an efficient statistical emulator of ENSO dynamics in comprehensive climate models while retaining a clear physical interpretation of the governing processes.

Beyond reproducing climate model behavior, mCRO enables process-oriented analyses of ENSO dynamics. For example, by fitting the Recharge Oscillator to 30-year sliding windows of CESM1-LE simulations, the temporal evolution of the fitted parameters can be tracked. This makes it possible to identify which physical processes—such as changes in ocean–atmosphere coupling, damping, nonlinear feedbacks, or stochastic forcing—are primarily responsible for changes in ENSO characteristics over time. Such analyses provide a computationally efficient framework for attributing changes in ENSO dynamics in climate model simulations and can be readily extended to CMIP6 models and future climate projections.

Local helper functions#

These helper functions replace convenience functions used by the Python notebook.

function par_out=aggregate_RO_parameters(fit_results,method)
% Aggregate 16-element CRO parameter cell arrays across ensemble members.


nMember=numel(fit_results);
nPar=numel(fit_results{1});
par_out=cell(nPar,1);


for ip=1:nPar
    max_len=0;
    for im=1:nMember
        v=fit_results{im}{ip};
        if ~isempty(v)
            max_len=max(max_len,numel(v));
        end
    end


    if max_len==0
        par_out{ip}=[];
        continue
    end


    values=nan(nMember,max_len);
    for im=1:nMember
        v=fit_results{im}{ip};
        if ~isempty(v)
            values(im,1:numel(v))=v(:).';
        end
    end


    switch lower(method)
        case "mean"
            out=mean(values,1,'omitnan');
        case "median"
            out=median(values,1,'omitnan');
        case "std"
            out=std(values,0,1,'omitnan');
        otherwise
            error("Unknown aggregation method: %s",method)
    end


    if numel(out)==1
        par_out{ip}=out;
    else
        par_out{ip}=out;
    end
end
end

function S=seasonal_statistic(X,stat_name)
% Return [12 x ensemble] seasonal statistics, assuming the series starts in January.


nMember=size(X,2);
S=nan(12,nMember);
for m=1:12
    idx=m:12:size(X,1);
    for im=1:nMember
        x=X(idx,im);
        switch lower(stat_name)
            case "std"
                S(m,im)=std(x,0,'omitnan');
            case "skewness"
                x=x(isfinite(x));
                if numel(x)>=3
                    S(m,im)=skewness(x,0);
                end
            otherwise
                error("Unknown statistic: %s",stat_name)
        end
    end
end
end


function h=plot_ensemble_spread(x,Y,label_text,line_color)
% Plot median and 10th-90th percentile spread across ensemble dimension.


med=median(Y,2,'omitnan');
lo=prctile(Y,10,2);
hi=prctile(Y,90,2);


if isempty(line_color)
    h=plot(x,med,'LineWidth',1.8,'DisplayName',label_text);
    c=h.Color;
else
    c=line_color;
    h=plot(x,med,'Color',c,'LineWidth',1.8,'DisplayName',label_text);
end


fill([x(:);flipud(x(:))],[lo(:);flipud(hi(:))],c, ...
    'FaceAlpha',0.15,'EdgeColor','none','HandleVisibility','off');
uistack(h,'top')
end


function [lags,acf,ccf]=ensemble_xcorr(T,H,maxlags)
% ACF of T and cross-correlation between T and H for each ensemble member.
% Positive cross-correlation lag is plotted as T leading H, matching the tutorial labels.


nMember=size(T,2);
lags=(-maxlags:maxlags).';
acf=nan(numel(lags),nMember);
ccf=nan(numel(lags),nMember);


for im=1:nMember
    t=T(:,im);
    h=H(:,im);
    good=isfinite(t) & isfinite(h);
    t=t(good);
    h=h(good);
    t=t-mean(t,'omitnan');
    h=h-mean(h,'omitnan');
    acf(:,im)=xcorr(t,t,maxlags,'coeff');
    ccf(:,im)=xcorr(t,h,maxlags,'coeff');
end
end


function [freq,P,SIG]=ensemble_pmtm(X,NW,fs)


% Multitaper PSD and AR(1) red-noise 95% significance spectrum
% for each ensemble member.


nMember=size(X,2);


P=[];
SIG=[];
freq=[];


for im=1:nMember


    x=X(:,im);
    x=x(isfinite(x));
    x=x-mean(x,'omitnan');


    % ---------------------------------------------------------
    % Multitaper power spectrum
    % ---------------------------------------------------------
    [pxx,f]=pmtm(x,NW,[],fs);


    % ---------------------------------------------------------
    % Lag-1 autocorrelation
    % ---------------------------------------------------------
    r1=corr(x(1:end-1),x(2:end));


    % ---------------------------------------------------------
    % AR(1) red-noise background spectrum
    %
    % S(f) = variance(x)*(1-r1^2) /
    %        (1+r1^2-2*r1*cos(2*pi*f/fs))
    % ---------------------------------------------------------
    rednoise=var(x,1) .* ...
        (1-r1^2) ./ ...
        (1+r1^2-2*r1*cos(2*pi*f/fs));


    % Scale the AR(1) spectrum so that its integrated variance
    % matches the variance represented by the PMTM spectrum.
    rednoise=rednoise .* ...
        (trapz(f,pxx)/trapz(f,rednoise));


    % ---------------------------------------------------------
    % 95% significance level
    %
    % For multitaper spectrum with NW=3, use approximately
    % 2*NW degrees of freedom.
    % ---------------------------------------------------------
    dof=2*NW;


    sig95=rednoise .* chi2inv(0.95,dof)/dof;


    if isempty(P)
        freq=f;
        P=nan(numel(f),nMember);
        SIG=nan(numel(f),nMember);
    end


    P(:,im)=pxx;
    SIG(:,im)=sig95;


end


end


function h=plot_spectrum_spread(freq,P,label_text,line_color)
med=median(P,2,'omitnan');
lo=prctile(P,5,2);
hi=prctile(P,95,2);


if isempty(line_color)
    h=loglog(freq,med,'LineWidth',1.5,'DisplayName',label_text);
    c=h.Color;
else
    c=line_color;
    h=loglog(freq,med,'Color',c,'LineWidth',1.5,'DisplayName',label_text);
end

fill([freq(valid);flipud(freq(valid))],[lo(valid);flipud(hi(valid))],c, ...
    'FaceAlpha',0.15,'EdgeColor','none','HandleVisibility','off');
set(gca,'XScale','log','YScale','log')
uistack(h,'top')
end


function patch_band(xrange,yl,alpha_value)
patch([xrange(1) xrange(2) xrange(2) xrange(1)], ...
      [yl(1) yl(1) yl(2) yl(2)], ...
      [0.5 0.5 0.5], ...
      'FaceAlpha',alpha_value,'EdgeColor','none','HandleVisibility','off');
end
